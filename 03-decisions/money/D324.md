D324 — LOCKED (2026-08-11, supersedes D61's manual-refund remedy). An upheld-picker dispute resolution refunds the captured claim fee itself, through Stripe, as part of the resolve action — never by operator hand-work in the Stripe dashboard. Mechanism: refund_captured_claim in stripe_service.py, called by the admin resolve handler's upheld_picker branch before any write, so a failed refund fails the whole resolution (502, retryable). Idempotent two ways: a claim already carrying refund_id skips Stripe, and the Stripe call carries idempotency key refund_claim_{claim_id}, so a retry after a lost response cannot refund twice. Only fires when captured_at is set; a released or lapsed hold has nothing to return and resolves as before. Writes refund_id and refunded_at, which the receipt timeline already renders. D61's ban stands for every OTHER surface: no user-initiated refund exists and none is planned; this is the admin resolution path only.
