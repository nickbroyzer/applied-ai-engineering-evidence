**D207 — Giver No-Show Policy**

STATUS: LOCKED (product) — implementation pending. RAG: LOCKED_DECISION_PENDING_IMPLEMENTATION.

The $2 is a platform fee held as a Stripe manual-capture pre-authorization (capture_method="manual", stripe_service.py:155); it becomes a real charge only on pickup confirmation (claims.py:497), giver-marks-picker no-show (claims.py:834), or the post-window auto-capture timer (post_window_sweeper.py:366). Giver receives $0.

Policy: refund the picker liberally, penalize the giver conservatively. A false picker report cannot profit (it only returns the picker's own $2) but could smear giver trust, so a single report never penalizes the giver. Picker-only report.

Giver trust penalty fires only on confirmed fault: (1) giver admits it, (2) giver does not respond in the response window, or (3) admin/CX confirms a cross-picker pattern. Thresholds: 2 reports from 2 different pickers within 30 days → CX review; no auto-penalty from pattern alone; 3 confirmed no-shows within 90 days → stronger account review.

Public wording: "You won't be charged for a missed pickup — and if you've already been charged, we'll refund you once we confirm."

BUILD REQUIRED (net-new): a picker "report giver no-show" action (endpoint + mobile button) that moves the claim to a new "under review" status. The auto-capture sweep only touches claims with status IN ('authorized','pickup_scheduled') (post_window_sweeper.py:56), so a review status outside that set suspends the timer with no change to the sweeper. Verify the full ck_claims_status constraint in models.py before writing the migration for the new status.
