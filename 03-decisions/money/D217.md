**D217 — Hold-expiry backstop resolves as cancel, never capture.** A claim that reaches its stored authorization-hold expiry without a completed pickup is cancelled and the hold voided. It is never captured. Voiding an uncaptured authorization costs the platform nothing; capturing before a pickup has occurred exposes the platform to a $15 dispute fee per contested charge, which exceeds the margin on roughly nine completed claims. The good-faith re-claim cost is accepted deliberately. The sweep selects on the stored per-hold expiry value only — never a day count, never a computed offset from the authorization timestamp — and carries no lower bound, so a hold that has already lapsed still triggers cancel-and-relist. Order is load-bearing: void in Stripe first, write the cancelled status only after the void returns successfully; a database row marked cancelled with a live hold attached is the exact leak D212 exists to close. Corollary, binding: a claim with no live authorization is not a claim, and no pickup proceeds without platform compensation. Rows carrying no stored expiry are excluded from this sweep and remain on the existing no-coordination auto-cancel path; no backfill is performed. The cancel-never-capture principle above still holds for any future expiry handling. Filed Session 332, superseded Session 333. LOCKED.
