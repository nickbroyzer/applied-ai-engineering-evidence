**D23 — Per-event money rules across terminal claim transitions** *(Session 98)*
Operationalizes D9 ($2 forfeiture principle) by codifying which terminal transition captures the hold, which voids it, and how a picker-cancel close to pickup time is treated. Does not supersede D9; D9 remains as written.

Mechanics:
1. No-show: picker accepted the appointment via the `authorized` state and did not appear. The `mark_no_show` route handler captures the full $2 hold to Zelbi. No refund. No void. The $2 forfeit per D9 is realized at this transition.
2. Cancel: either party walks away before the appointment is honored. The `cancel_claim` route handler voids the uncaptured hold. No money moves. No charge appears on the picker's card.
3. Giver-fails-to-show: not a no-show. Treated as a giver-initiated cancel. The picker is not penalized — hold is voided, no trust event written against the picker, listing returns to `active`.
4. Picker-cancel grace window: free cancel up to 2 hours before `claim.pickup_scheduled_at`. Inside the 2-hour window, picker-cancel transitions to capture (forfeit), not void. Giver-cancel always voids regardless of timing.

Implementation note: the current `mark_no_show` handler at `app/routers/claims.py` line 383 calls `cancel_payment_intent`, which contradicts D23 mechanic 1 and D9. This is a known bug, scheduled for fix in Session 99 as the first build task after D23 is filed. The picker-cancel grace-window logic is also a Session 99 build task — current `cancel_claim` handler does not branch on timing.
