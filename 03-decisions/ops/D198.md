**D198 — Two-lane notification policy** *(Session 313, 2026-06-29)*
Decision: Notifications are split into two lanes. Instant lane (messages, claims, payments, security alerts) fires `send_push` per-event, writing both a push and an inbox row on every trigger. Digest lane (recommendations, saved-deadline reminders, listing-expiry nudges, pickup reminders) writes inbox rows only at event time; a single daily summary push is sent per user per day by `send_daily_digest_summaries` in `backend/app/services/notification_service.py`. A user who has no digest-lane inbox events that day receives no push. The digest is gated: users who have already received a daily summary push today are skipped.

Rationale: Push fatigue from four daily cron jobs each firing individual pushes was a known risk. Consolidating digest-lane jobs into one daily summary push caps the daily push count at 1 (for digest) + N (for instant events), matching user expectations for ambient background notifications vs. time-sensitive events.

Scope: `backend/app/services/notification_service.py` (two-lane split + `send_daily_digest_summaries`); `backend/app/jobs/run_daily_jobs.py` (runner calls `send_daily_digest_summaries` after digest scan jobs). No mobile changes required for the digest; mobile inbox already renders all notification types.
