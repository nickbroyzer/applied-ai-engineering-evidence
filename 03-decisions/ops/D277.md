**D277 (LOCKED Session 380)** — Background and badge polls must never be able to end a session. The unread-count and notification-count pollers in `mobile/app/(app)/_layout.tsx` ran on a 30-second interval with an empty dependency array and no authentication gate, so they fired during the window in which `restoreSession()` has set `isAuthenticated` true but `/auth/me` has not yet resolved. Their 401s went through the interceptor's refresh-then-logout path and logged the user out twice per cycle, once per poller. Two changes: the pollers are now gated on `isAuthenticated` and a non-null user, and the interceptor carries a `NON_SESSION_ENDING_PATHS` list — `/users/push-token`, `/messages/unread-count`, `/notifications` — whose 401s reject to the caller without a refresh or a logout. Consequence accepted: a genuinely dead session now surfaces on a foreground request rather than on a background poll, and a badge may read zero when it should not. Any future background poller added to the app is added to that list. Shipped `5d02d80`.
