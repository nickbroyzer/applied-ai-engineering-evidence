**D276 (LOCKED Session 380)** — The primary Supabase client must never use the PKCE flow. The React Native runtime has no WebCrypto, so under PKCE the code challenge degrades to plain and both email OTP verification and session refresh are rejected. A rejected refresh reaches the axios 401 interceptor, which calls `logout()`, which routes to the login screen — this was the mechanism behind the login screen resetting every ~30 seconds before a code could be entered. Session 231 removed `flowType` at `c61a3a6` for this reason; commit `201ff6a` reinstated it as a single unremarked line while adding OAuth, and it stayed for two months. Browser-redirect OAuth (Google, and Apple on non-iOS) does require PKCE because `exchangeCodeForSession` needs the stored code verifier, so it now runs on a second client, `getOAuthSupabase()`, with its own `storageKey` `'zelbi-oauth-auth-token'` and `autoRefreshToken` false. Apple on iOS is native `signInWithIdToken` and stays on the primary client. Shipped `5d02d80` in `mobile/utils/supabase.ts` and `mobile/utils/oauth.ts`. Do not add `flowType` back to `getSupabase()`.
**Status: LOCKED**
