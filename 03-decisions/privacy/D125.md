**D125 — Map-privacy approximate-point system (Session 237, locked)**
Status: OPEN (locked, unbuilt). Gates the entire Discover map feature.
Decision: non-claimers receive an approximate display point for every listing; true coordinates are revealed only at the paywall seam.
Fork 1 — fuzz at storage time: approximate point persisted in two new columns, computed once at listing create and recomputed on coordinate update. Tradeoff: one migration plus two columns per row, in exchange for stability-for-free and zero per-request cost.
Fork 2 — stability via persistence plus a listing-id-seeded generator: the stored value never changes per request; the seed makes any future re-fuzz backfill reproducible.
Fork 3 — reveal via a single shared resolver called only from the listing detail route: true coordinates returned only when the caller is the giver, or holds a claim whose status is one of authorized, pickup_scheduled, completed, or auto_captured. The pending_payment, no_show, and cancelled states do not reveal. The nearby route never reveals true coordinates to anyone.
Verified against source Session 237: claim status check constraint carries seven values; the reveal set is the four-value subset above. Nearby SQL computes distance and the radius predicate from true coordinates inside the CTE; only the returned columns become approximate.
Build dependency: this is Stage 1 of the Discover build plan and blocks all map front-end stages.
