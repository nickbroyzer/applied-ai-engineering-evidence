**D21 — Picker no-show strike rule (replaces §9 escalation ladder)** *(Session 97)*
The §9 no-show escalation ladder (a strike count inside a rolling window → a fixed suspension, escalating tiers thereafter; **tuned constants withheld**) was specified before D9 locked the $2 pickup price. Under D9, the picker forfeits $2 per no-show, which is sufficient deterrent for one-off flaking. The escalating ladder is replaced with a single-tier punctuated rule.

Locked mechanics:
- Threshold: STRIKE_THRESHOLD confirmed `mark_no_show` events on the picker, in a rolling window. **Tuned constants withheld.**
- "Confirmed no-show" = giver-marked via the existing `mark_no_show` claim action only. Picker-initiated cancellations do not count toward this rule.
- Consequence: a fixed-duration time-out on the picker account. **Tuned constant withheld.**
- Counter behavior: resets to zero after the time-out is served. The rule fires again on the next full cycle, with no escalation between cycles.
- $2 forfeit per individual no-show: unchanged from D9, applies independently of strike count.

Time-out behavior:
- New claims: blocked for the time-out duration.
- Existing in-flight claims at time-out start: claim is cancelled, listing is released back to `active` status, the picker's PaymentIntent is voided (pre-authorization, not yet captured — see D22 verification item). The released listing is visible in the feed for other pickers to claim.
- The picker's existing message threads on cancelled claims close with the claim, consistent with Phase 5 cancellation behavior.

Build scope (Phase 6 STEP 3):
- New `user_strikes` accrual (column on users or separate table, schema TBD in build plan).
- Wire strike write into the existing `mark_no_show` handler in `claims.py`.
- Time-out enforcement: block new claim creation when the picker is currently in a time-out window.
- Cancel-and-release flow: when the final strike fires, find all in-flight claims for that picker, cancel them, release the listings, void the PaymentIntents.
- Counter reset logic: zero strikes when the time-out end date passes.
