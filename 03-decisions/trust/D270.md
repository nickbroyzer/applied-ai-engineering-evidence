**D270 (LOCKED Session 376)** — Rule 1 (new account + manual listing) is deleted, not disabled. It fired when an account under 24 hours old published a listing with `ai_generated` false. Verified this session: `mobile/app/(give-flow)/give-publish.tsx` hardcodes `ai_generated: true` and is the only publish path in the app, with no manual fallback and no conditional — so no real user could ever trigger the rule, and its false-positive rate is exactly zero. But the same fact empties it of value: the only caller that can send `false` is something other than the app, and the flag is client-supplied, so any scripted attacker who has inspected a single request sends `true` and passes. It caught nobody who had looked. Deleted rather than kept as a silent flag-only signal, because a defense that protects nothing is worse than none — it gets counted as protection when reasoning about coverage. The real version of this control is server-side: verify that a photo analysis actually occurred for the submitted photo before trusting the flag. That is a genuine build, filed as future work, not launch-blocking. Consequence to hold: listing-creation checks now run rules 2 and 6 only, since rule 5 (duplicate photo hash) remains deferred — the posting-time scam surface is a tempo guard and a keyword list. Three rule-1 tests removed; `test_scam_detection.py` is 41 passed. Commit `2e93f75`, deployed.
